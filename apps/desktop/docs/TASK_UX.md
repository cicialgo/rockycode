# 任务模型、审批与 HTML 预览

## 每个任务选择自己的模型

新建任务后，输入框上方的「任务模型」可以立即选择已配置凭证的模型。模型与任务一起保存，重启后保留；切换其他任务会显示该任务自己的模型。运行中的任务先停止再切换；另一个任务仍在运行不会阻止当前空闲任务切换。

新任务以启动时的 CLI 默认模型为初始值，之后独立保存。旧任务首次迁入时固定为本次启动默认值。客户端切换任务模型不再修改 CLI 配置、进程默认模型或其他任务的连接。

## 三种审批模式

| 模式 | 安全读取 | 工作区内文件修改 | Shell、网络、MCP 工具 |
| --- | --- | --- | --- |
| 修改前确认 | 直接执行 | 先确认 | 先确认 |
| 自动编辑工作区（默认） | 直接执行 | 直接执行 | 先确认 |
| 减少确认 | 直接执行 | 直接执行 | 跳过逐次询问，安装、联网等命令也可能直接执行 |

越界读取在前两种模式中需要确认。核心策略禁止的命令在所有模式中仍然被拦截。选项只控制工具调用的审批，不改变操作系统授权或现有 Shell 沙箱配置。手动「本会话允许」仍按当前任务中的工具名或命令程序记忆；危险命令不继承普通命令的会话授权。

输入区常驻当前模式的说明，问号按钮提供完整对照。外部 MCP/LSP 进程的首次启动在所有模式中都单独确认。

[Codex 官方文档](https://learn.chatgpt.com/docs/agent-approvals-security)把沙箱范围与审批策略分开：`workspace-write` 加 `on-request` 可以在工作区内自动工作，越界时请求授权。Rocky 的默认模式仅在交互意图上类似，不能视为同一套 OS 沙箱。[Codex Auto-review](https://learn.chatgpt.com/docs/sandboxing/auto-review)由独立审查模型判断授权请求，保留原有边界；Rocky 目前没有对应审查器，「减少确认」只是减少工具提示。将来若引入自动审查，应独立建模为审批者，不能把现在的 `yolo` 改名冒充该功能。公开文档核对日期：2026-10-23。

## MCP 从哪里来，连接意味着什么

MCP 是让助手调用另一个程序提供的工具的协议。共享核心会发现工作区 `.mcp.json`，以及已有的 Claude Code、Claude Desktop 和 `~/.codex/config.toml` 中的 stdio 配置；未受信任的项目配置不会自动启动，HTTP MCP 仍不在当前支持范围内。

连接卡显示实际服务名、配置来源与启动命令。Codex 来源会明确显示「Codex · ~/.codex/config.toml」，说明是自动发现的已有配置。仅凭服务名不推断用途或权限，也不声称本地进程受到 Renderer 沙箱限制。

- 「此次连接」只允许这次启动。
- 「本次应用运行期间记住此连接」覆盖同一工作区、同一服务/命令/参数/来源和显式环境配置，可供多个任务复用，运行环境重启即失效。其他服务或配置变更仍需要确认。
- 「暂不连接，继续任务」不启动该服务，任务可以继续处理其他工作。

连接授权和工具调用审批分开；不会修改 Codex 或 Claude 配置。环境配置以摘要绑定授权，不向界面发送凭证内容。

Codex 的默认 MCP 配置位置与跨客户端使用方式参见[官方 MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)。Rocky 当前的发现范围以自己的实现为准。

## 提示词预设

输入框左侧可以打开预设列表。预设是名称加提示词正文，所有任务共用，保存在桌面用户数据目录，不进入项目仓库。

- 可以从当前输入保存，也可以新建后填写名称和正文。
- 可以修改名称和正文，或删除。
- 使用一条预设会替换任务输入框中的文字。输入框已有不同的非空草稿时先确认，避免直接丢掉正在写的内容。空输入则直接填入。
- 预设不保存模型、审批模式或凭证。

## 在客户端预览 HTML

`create_artifact` 产物生成后自动在任务右侧预览。回复中的工作区 `.html` / `.htm` 链接也可以点击预览。产物列表与任务记录一起保存；可以关闭、重新打开或刷新。右上角 ↗ 按钮才会将文件交给系统默认浏览器（例如 Chrome）。不会修改默认浏览器设置。

内嵌预览默认静态、离线：保留内联样式、SVG/data 图片与排版，但脚本、内联事件和 Worker 均不执行。iframe 使用空 `sandbox`，协议响应头同时设置 `script-src 'none'` 与不含放行项的 `sandbox`。网络请求、外部脚本/样式/图片、嵌套页面、表单提交、弹窗和顶层跳转继续受限。HTML 使用独立的沙箱来源，不能访问客户端接口或父页面数据。只读取所选工作区内的 UTF-8 HTML 普通文件，上限 1 MB；POSIX 读取逐层使用目录描述符和禁止跟随符号链接的打开方式，防止读取时路径替换。

Rocky 仍可生成完整交互式 HTML；预览策略不会清洗或改写原文件，不影响 CLI/TUI 的产物功能。右上角 ↗ 是显式打开原文件的入口，浏览器会执行原有脚本，界面会说明这个区别。没有自动外部打开或内嵌「信任后运行脚本」开关。不要为了让预览交互恢复而添加 `allow-scripts` 或 `allow-same-origin`。

静态模式减少脚本驱动的攻击面，并不阻止 Chromium 解析 HTML/CSS、图片、字体或 SVG；这些内容仍可能触发引擎缺陷。保留展示兼容性是本次有意的取舍，不代表已实现格式白名单或所有 Chromium 漏洞均已缓解，Electron 安全升级仍须独立跟进。

预览与笔记共用右侧区域，打开其中一个会收起另一个。内嵌预览不是完整网站托管环境；依赖外部资源的页面可由用户显式选择在浏览器打开。

## 本轮验证

- `npm run check`：锁文件策略、TypeScript、静态构建、31 项单元测试。
- 桌面运行时：87 项测试通过，含实际共享核心的模型切换、真实本地工具、产物生成无外部浏览器调用、持久化，以及 HTML 读取边界。
- `npm run test:e2e`：原有 Electron 离线交互回归通过，包括中英文、900×620 窗口、审批、停止、草稿和笔记。
- `npm run test:e2e:task`：专项验收入口，覆盖任务模型隔离、MCP 来源与连接授权、静态 HTML 的脚本阻断、样式保留与浏览器箭头。静态策略新增断言需重新在真实 Electron 窗口验收；旧版交互测试通过记录不能作为此策略的验收。
- 受影响核心：Runtime、Artifact、Permission、MCP 冒烟通过。

所有模型回复使用离线 fixture 或替身，不产生真实模型调用。验收平台为 macOS，其他平台未在本轮实机验收。
